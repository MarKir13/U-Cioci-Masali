# U Cioci Masali

Reconstruction of the online shop [magiczne-indie.pl](https://www.magiczne-indie.pl/) on PrestaShop,
built as a team project for the *Biznes Elektroniczny* course at Gdansk University of Technology.

> Product data is scraped from the source shop for educational purposes only.
> This shop must not be publicly available on the internet.

## Tech stack

| Component | Version |
|---|---|
| PrestaShop | 8.2.8 (official image `prestashop/prestashop:8.2.8-8.1-apache`) |
| PHP | 8.1 (Apache) |
| Database | MariaDB 10.11.18 |
| HTTPS proxy | nginx 1.28.0 (`nginx:1.28.0-alpine`), self-signed certificate |
| Containers | Docker Engine + Docker Compose v2 |
| Scraper | Python 3.12, `requests`, Protego, pydantic, pytest (versions in `scraper/requirements.txt`) |

Our own code (child theme `ciocia`, modules, PHP config) lives in `shop/` and is built on top of
the official image. PrestaShop itself is not stored in this repository.

## Running the shop

Requirements: [Docker Desktop](https://www.docker.com/products/docker-desktop/) (or Docker Engine with Compose v2) and Git.

1. Clone the repository and enter it:
   ```sh
   git clone <repo-url>
   cd U-Cioci-Masali
   ```
2. Create the local configuration from the template (works as-is for local use):
   ```sh
   cp deploy/.env.example deploy/.env
   ```
3. Build and start the containers:
   ```sh
   docker compose -f deploy/compose.yaml up -d --build
   ```
4. Wait for the first-time installation to finish (about 3–5 minutes). It is done when the log shows
   `Starting web server`:
   ```sh
   docker compose -f deploy/compose.yaml logs -f shop
   ```
5. Open the shop (HTTPS only; http://localhost:8080 redirects there with 301):
   - Storefront: https://localhost:8443
   - Admin panel: https://localhost:8443/admin-ciocia
     (login: `ADMIN_MAIL` / `ADMIN_PASSWORD` from `deploy/.env`)

   The certificate is self-signed (generated by the `proxy` container on first start), so the
   browser shows a warning the first time: choose *Advanced* → *Proceed to localhost*.
   For command-line tools use `curl -k`; for Lighthouse and Playwright ignore certificate errors.

### HTTPS

The `proxy` container (nginx, `deploy/proxy/`) is the only one with published ports. It ends TLS
and passes requests to the shop over the internal Docker network. The certificate and key are
generated into the `certs` volume, so they stay the same across `down` / `up` and are made again
only after `down -v`. They are never stored in the repository. Design notes:
[ADR 0002](docs/adr/0002-https-proxy-with-self-signed-certificate.md).

> **Upgrading an existing install** (from before HTTPS): in `deploy/.env` replace `SHOP_PORT`
> with `HTTP_PORT=8080` and `HTTPS_PORT=8443` (see `deploy/.env.example`), then reinstall once with
> `docker compose -f deploy/compose.yaml down -v` and `up -d --build`. The shop domain and SSL
> settings are written to the database at install time, so the old install keeps redirecting to
> plain HTTP.

### Everyday commands

| Task | Command |
|---|---|
| Stop the shop (data is kept) | `docker compose -f deploy/compose.yaml down` |
| Apply changes from `shop/` (theme, modules, config) | `docker compose -f deploy/compose.yaml up -d --build` |
| Reset everything and reinstall from scratch | `docker compose -f deploy/compose.yaml down -v` |

PrestaShop's cache (`var/cache/prod` and `var/cache/dev`) is cleared automatically on every start,
so new module template overrides take effect after `up -d --build` with no manual step. The first
page load after a start takes a few seconds longer while the cache is rebuilt.

## Continuous integration

GitHub Actions runs three workflows:

| Workflow | When | What it checks |
|---|---|---|
| [`ci.yml`](.github/workflows/ci.yml) | Every pull request and every push to `main` | `scraper`: ruff and the scraper unit tests. `repo-hygiene`: secrets (gitleaks) and repository limits over the history of `main` plus the PR. `ci-gate`: passes only if both jobs passed |
| [`pr-policy.yml`](.github/workflows/pr-policy.yml) | A pull request is opened, updated or relabelled | `ai-log`: a PR labelled `ai-assisted` must add or update a row in `docs/AI_LOG.md` |
| [`secret-scan.yml`](.github/workflows/secret-scan.yml) | Nightly, or by hand from the Actions tab | Secrets and repository limits over every branch, the way the lecturer measures it |

A pull request must have passing `ci-gate` and `ai-log` checks before it is merged.

`repo-hygiene` scans every commit of the PR, because merge commits keep the branch history on `main`. A secret that
is removed in a later commit therefore still fails the check: rewrite the branch (and force-push it, never `main`)
instead. A red nightly scan means some branch has a secret in its history; clean that branch or delete it.

The repository limits are set at the top of
[`.github/scripts/check-repo-limits.sh`](.github/scripts/check-repo-limits.sh): no file over 10 MB in history, at most
200 MB in total, at most 20 images in `scraper-results/`, and no `.env` file (other than `.env.example`), private key
or certificate in any commit.

gitleaks runs with its default rules and nothing ignored, as the lecturer runs it. Fix a finding by removing the secret;
do not silence it. CI reports lines marked `gitleaks:allow` anyway, and the limits script fails if `.gitleaks.toml` or
`.gitleaksignore` is committed, because gitleaks would read either one from the repository.

To run the same checks locally, install the tools once:

```sh
pip install ruff==0.17.3
pip install -r scraper/requirements.txt
```

| Check | Command |
|---|---|
| Lint | `ruff check .` |
| Formatting (`ruff format .` fixes it) | `ruff format --check .` |
| Scraper unit tests (from `scraper/`) | `python -m pytest` |
| Secret scan, as on a PR (needs Docker) | `docker run --rm -v "$PWD:/repo:ro" zricethezav/gitleaks:v8.30.1 git /repo --no-banner --redact --ignore-gitleaks-allow --log-opts="HEAD"` |
| Secret scan, every branch | The same command with `--log-opts="--all"` |
| Repository limits (add `--all` for every branch) | `sh .github/scripts/check-repo-limits.sh` |

In Git Bash on Windows, put `MSYS_NO_PATHCONV=1` in front of the `docker run` command, otherwise the `/repo` path is
rewritten. `--all` also covers your local branches, so it can report something that is not on GitHub.
