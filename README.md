# U Cioci Masali

Reconstruction of the online shop [magiczne-indie.pl](https://www.magiczne-indie.pl/) on PrestaShop,
built as a team project for the *Biznes Elektroniczny* course at Gdansk University of Technology.

> Product data is scraped from the source shop for educational purposes only.
> This shop must not be publicly available on the internet.

## Tech stack

| Component | Version |
|---|---|
| PrestaShop | 8.2.8 (official image `prestashop/prestashop:8.2.8-8.1-apache`) |
| PHP | 8.1 (Apache) |
| Database | MariaDB 10.11.18 |
| HTTPS proxy | nginx 1.28.0 (`nginx:1.28.0-alpine`), self-signed certificate |
| Containers | Docker Engine + Docker Compose v2 |
| Scraper | Python 3.12, `requests`, Protego, pydantic, pytest (versions in `scraper/requirements.txt`) |
| E2E tests | Playwright 1.64.1 (headless Chromium) on Node.js 24, see [E2E tests](#e2e-tests) |

Our own code (child theme `ciocia`, modules, PHP config) lives in `shop/` and is built on top of
the official image. PrestaShop itself is not stored in this repository.

## Running the shop

Requirements: [Docker Desktop](https://www.docker.com/products/docker-desktop/) (or Docker Engine with Compose v2) and Git.

1. Clone the repository and enter it:
   ```sh
   git clone <repo-url>
   cd U-Cioci-Masali
   ```
2. Create the local configuration from the template (works as-is for local use):
   ```sh
   cp deploy/.env.example deploy/.env
   ```
3. Build and start the containers:
   ```sh
   docker compose -f deploy/compose.yaml up -d --build
   ```
4. Wait for the first-time installation to finish (about 3–5 minutes). It is done when the log shows
   `Starting web server`:
   ```sh
   docker compose -f deploy/compose.yaml logs -f shop
   ```
5. Open the shop (HTTPS only; http://localhost:8080 redirects there with 301):
   - Storefront: https://localhost:8443
   - Admin panel: https://localhost:8443/admin-ciocia
     (login: `ADMIN_MAIL` / `ADMIN_PASSWORD` from `deploy/.env`)
   - E-mails sent by the shop (registration, orders): http://localhost:8025 (Mailpit)

   The certificate is self-signed (generated by the `proxy` container on first start), so the
   browser shows a warning the first time: choose *Advanced* → *Proceed to localhost*.
   For command-line tools use `curl -k`; for Lighthouse and Playwright ignore certificate errors.

### HTTPS

The `proxy` container (nginx, `deploy/proxy/`) is the only one with published ports. It ends TLS
and passes requests to the shop over the internal Docker network. The certificate and key are
generated into the `certs` volume, so they stay the same across `down` / `up` and are made again
only after `down -v`. They are never stored in the repository. Design notes:
[ADR 0002](docs/adr/0002-https-proxy-with-self-signed-certificate.md).

> **Upgrading an existing install** (from before HTTPS): in `deploy/.env` replace `SHOP_PORT`
> with `HTTP_PORT=8080` and `HTTPS_PORT=8443` (see `deploy/.env.example`), then reinstall once with
> `docker compose -f deploy/compose.yaml down -v` and `up -d --build`. The shop domain and SSL
> settings are written to the database at install time, so the old install keeps redirecting to
> plain HTTP.

### Everyday commands

| Task | Command |
|---|---|
| Stop the shop (data is kept) | `docker compose -f deploy/compose.yaml down` |
| Apply changes from `shop/` (theme, modules, config) | `docker compose -f deploy/compose.yaml up -d --build` |
| Reset everything and reinstall from scratch | `docker compose -f deploy/compose.yaml down -v` |

PrestaShop's cache (`var/cache/prod` and `var/cache/dev`) is cleared automatically on every start,
so new module template overrides take effect after `up -d --build` with no manual step. The first
page load after a start takes a few seconds longer while the cache is rebuilt.

### Shop settings: currency, delivery, payments, e-mail

Right after the first install, `shop/scripts/setup/configure-shop.php` sets up the shop for Poland:
PLN (plus EUR in the selector, as on the source shop), Poland as the only country, Polish VAT groups
(23, 8, 5, 0 %), two carriers priced by weight up to 50 kg, free delivery from 2000 PLN gross,
bank transfer and cash on delivery (no cheque), invoices, and e-mail through Mailpit.

All values are in [`shop/config/shop-settings.php`](shop/config/shop-settings.php); the header banner
("Dostawa od 2000 zł gratis") reads the threshold from the shop configuration, not from the template. To change one,
for example the free delivery threshold, edit that file, then rebuild and run the script again
(it is idempotent: a second run changes nothing and creates no duplicates):

```sh
docker compose -f deploy/compose.yaml up -d --build
docker compose -f deploy/compose.yaml exec shop runuser -u www-data -- php /opt/ciocia/scripts/setup/configure-shop.php
```

In Git Bash on Windows, put `MSYS_NO_PATHCONV=1` in front of the second command. Settings changed in
the admin panel are lost on `down -v` and missing on other machines, so change them in this file.

> **Install made before this script existed** (prices in EUR, demo carriers): run the two commands
> above once. The script also imports the Polish VAT groups that the old install is missing.


## E2E tests

The Playwright suite in [`tests/`](tests/) runs the W4 purchase scenario in headless Chromium against a running
shop. It has its own [`package.json`](tests/package.json), separate from the ESLint tools in the root one.

Requirements: [Node.js](https://nodejs.org/) 24 and a running shop (see [Running the shop](#running-the-shop)).

1. Install the dependencies and the browser once, from `tests/`:
   ```sh
   cd tests
   npm ci
   npx playwright install chromium
   ```
   On Linux without a desktop (CI, a cluster node) use `npx playwright install --with-deps chromium`.
2. Run the whole suite, from `tests/`:
   ```sh
   npm test
   ```

The shop address comes from `BASE_URL` (default `https://localhost:8443`); the self-signed certificate is accepted.

| Shell | Command |
|---|---|
| bash, Git Bash | `BASE_URL=https://localhost:8443 npm test` |
| PowerShell | `$env:BASE_URL = "https://localhost:8443"; npm test` |

The host in `BASE_URL` must be the shop's own domain (`PS_DOMAIN`, set at install time), because PrestaShop
redirects every other host name there. The smoke test fails if that happens.

Reports are written on every run; both folders are ignored by git:

| Report | Where |
|---|---|
| HTML: every step, plus a screenshot and a trace when a test fails | `tests/playwright-report/index.html`, open it with `npm run report` |
| JUnit XML | `tests/test-results/junit.xml` |

Products and quantities are picked at random from a seed, which both reports show (`seed` annotation). To repeat
a failed run with the same picks, pass that seed: `E2E_SEED=123456789 npm test` (PowerShell:
`$env:E2E_SEED = "123456789"; npm test`). The new customer's e-mail is unique on every run, with or without a seed,
so the suite can run many times on the same shop.

| Path | Contents |
|---|---|
| `tests/tests/` | `smoke.spec.js` (home page over HTTPS, no console errors) and `order.spec.js` (the W4 scenario, one step per point of the brief) |
| `tests/pages/` | One file per area of the shop (catalog, search, cart, account, checkout, orders) with its selectors and actions |
| `tests/support/` | Shared code: fixtures (`test`, `rng`, `consoleErrors`), seeded random numbers, test data |

Rules for new tests: import `test` and `expect` from `tests/support/fixtures.js`, keep selectors in `tests/pages/`,
and never wait a fixed time. Wait on a condition instead (`expect(...)`, `waitForURL`, `waitForResponse`);
`npx eslint` fails on `waitForTimeout`. The whole run must stay under 5 minutes, and Playwright stops it after 4.


## Continuous integration

GitHub Actions runs three workflows:

| Workflow | When | What it checks |
|---|---|---|
| [`ci.yml`](.github/workflows/ci.yml) | Every pull request and every push to `main` | `scraper`: ruff and the scraper unit tests. `repo-hygiene`: secrets (gitleaks) and repository limits over the history of `main` plus the PR. `infra-lint`: Dockerfiles, shell scripts, the compose file, PHP syntax and JavaScript (theme and E2E tests). `ci-gate`: passes only if all jobs passed |
| [`pr-policy.yml`](.github/workflows/pr-policy.yml) | A pull request is opened, updated or relabelled | `ai-log`: a PR labelled `ai-assisted` must add or update a row in `docs/AI_LOG.md` |
| [`secret-scan.yml`](.github/workflows/secret-scan.yml) | Nightly, or by hand from the Actions tab | Secrets and repository limits over every branch, the way the lecturer measures it |

A pull request must have passing `ci-gate` and `ai-log` checks before it is merged.

`repo-hygiene` scans every commit of the PR, because merge commits keep the branch history on `main`. A secret that
is removed in a later commit therefore still fails the check: rewrite the branch (and force-push it, never `main`)
instead. A red nightly scan means some branch has a secret in its history; clean that branch or delete it.

The repository limits are set at the top of
[`.github/scripts/check-repo-limits.sh`](.github/scripts/check-repo-limits.sh): no file over 10 MB in history, at most
200 MB in total, at most 20 images in `scraper-results/`, and no `.env` file (other than `.env.example`), private key
or certificate in any commit.

gitleaks runs with its default rules and nothing ignored, as the lecturer runs it. Fix a finding by removing the secret;
do not silence it. CI reports lines marked `gitleaks:allow` anyway, and the limits script fails if `.gitleaks.toml` or
`.gitleaksignore` is committed, because gitleaks would read either one from the repository.

`infra-lint` runs each check as its own step, so one run shows every problem:

| Step | Tool | What it catches |
|---|---|---|
| Dockerfiles | [hadolint](https://github.com/hadolint/hadolint) 2.15.1 | Untagged base images, unpinned packages, `ADD` instead of `COPY`, `cd` instead of `WORKDIR`, and shellcheck findings in `RUN` lines |
| Shell scripts | [shellcheck](https://www.shellcheck.net/) 0.11.0 on every tracked `*.sh` | Syntax errors, unquoted variables, commands that do not exist in POSIX `sh` |
| Compose file | `docker compose config --quiet` with `deploy/.env.example` | Unknown keys, undefined services or volumes, invalid ports, missing variables. Compose only warns about an unknown variable and leaves it empty, so the step fails on any output |
| PHP syntax | `php -l` from `php:8.1.34-cli` on every `*.php` under `shop/` | Syntax errors |
| JavaScript | [ESLint](https://eslint.org/) 10.13.0, recommended rules, browser globals ([`eslint.config.mjs`](eslint.config.mjs)) | Undefined variables, unused variables, unreachable code |

hadolint, shellcheck and PHP run from pinned Docker images, so nothing has to be installed for them. ESLint is pinned
in the root [`package.json`](package.json) and [`package-lock.json`](package-lock.json); npm is used only for these
development tools. When you update it, choose versions at least two weeks old and pass the matching date, so that
their dependencies are old enough too: `npm install --save-dev --save-exact eslint@<version> --before=<YYYY-MM-DD>`.

Fix a finding rather than silencing it. If a rule really does not fit, silence that one line and give the reason
above it, as `deploy/proxy/Dockerfile` does for `# hadolint ignore=DL3018`. Never turn a rule off for the whole
repository. The reasons are in [ADR 0003](docs/adr/0003-ci-checks-and-merge-policy.md).

To run the same checks locally, install the tools once. The linters run in Docker; ESLint needs Node.js 20.19+, 22.13+
or 24+:

```sh
pip install ruff==0.17.3
pip install -r scraper/requirements.txt
npm ci
```

| Check | Command |
|---|---|
| Lint | `ruff check .` |
| Formatting (`ruff format .` fixes it) | `ruff format --check .` |
| Scraper unit tests (from `scraper/`) | `python -m pytest` |
| Secret scan, as on a PR (needs Docker) | `docker run --rm -v "$PWD:/repo:ro" zricethezav/gitleaks:v8.30.1 git /repo --no-banner --redact --ignore-gitleaks-allow --log-opts="HEAD"` |
| Secret scan, every branch | The same command with `--log-opts="--all"` |
| Repository limits (add `--all` for every branch) | `sh .github/scripts/check-repo-limits.sh` |
| Dockerfiles | `docker run --rm -v "$PWD:/repo:ro" -w /repo hadolint/hadolint:v2.15.1 hadolint shop/Dockerfile deploy/proxy/Dockerfile` |
| Shell scripts | `git ls-files -z '*.sh' \| xargs -0 docker run --rm -v "$PWD:/repo:ro" -w /repo koalaman/shellcheck:v0.11.0` |
| Compose file (prints nothing when valid) | `docker compose -f deploy/compose.yaml --env-file deploy/.env.example config --quiet` |
| PHP syntax | `git ls-files -z 'shop/*.php' \| xargs -0 -r -n1 docker run --rm -v "$PWD:/repo:ro" -w /repo php:8.1.34-cli php -l` |
| JavaScript | `npx eslint` |

In Git Bash on Windows, put `MSYS_NO_PATHCONV=1` in front of `docker run`, or in front of `xargs` where the command
uses it, otherwise the `/repo` path is rewritten. `--all` also covers your local branches, so it can report something
that is not on GitHub. The compose check reads `deploy/.env.example` instead of your own `deploy/.env`, so it gives the
same result as CI and never shows your passwords.
