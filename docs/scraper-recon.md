# Scraper reconnaissance: magiczne-indie.pl

Findings from a manual survey of the source shop (29.10.2026), made before writing the scraper.
Selectors and numbers below were checked on the pages saved in
[`scraper/tests/fixtures/`](../scraper/tests/fixtures/).

## Summary

- The source shop runs **PrestaShop** with a custom theme and custom `ndx*` modules, so most data is
  available as structured JSON embedded in the page, not only as HTML.
- The sitemap lists **2167 products** and **314 categories**. Of those products, **1311 have at least 2 images**,
  so the requirement of 50 products with 2+ images is met easily.
- Every field required by the course is available, including the **VAT rate** and full-size images
  (1440 × 1440 px).

## robots.txt

- Generated by PrestaShop, plus an extra block for AI bots. Our scraper uses its own User-Agent and
  falls under `User-agent: *`.
- **No `Crawl-delay`**: we choose our own delay (planned: at least 1 s between requests).
- Disallowed and relevant to us:
  - `?q=`: faceted search filters
  - `?n=`: products per page, so we cannot enlarge listing pages
  - `?order=`: sorting
  - `/szukaj`: search
  - cart, account and order pages
- Allowed and needed by us: category pages, `?page=N` pagination, product pages, images.
- Sitemap: `https://www.magiczne-indie.pl/1_index_sitemap.xml`. It points to a single file,
  `1_pl_0_sitemap.xml` (about 1.4 MB).

## Sitemap

- URLs are wrapped in `<![CDATA[...]]>` inside `<loc>`, and must be stripped before use.
- URL types:
  - **Products:** `/{id}-{slug}.html`, 2167 URLs. Each has `<image:loc>` entries in the `large_default` (800 px) size.
  - **Categories:** `/{id}-{slug}` (no `.html`), 314 URLs.
  - **Other:** CMS pages, `?controller=module-...` links. These are ignored.

## Category tree

- The main menu (`ul#top-menu`) shows only 3 levels and **112 of 314** categories, so it is not enough on its own.
- Every category page has a JSON-LD `BreadcrumbList`. It gives the full path to the root, and therefore the parent of
  each category.
- Subcategory links on a category page: `div.subcategory a`.
- Category name: `h1.page-title-section`. The numeric id is the URL prefix (`/104-olejki-do-wlosow` → 104).
- Top-level categories in the menu: Kosmetyki (8), Żywność (193), Zdrowie (80), Różności (232), plus the special
  categories Na prezent (458) and Nowości (50). "Promocje" and "Himalaya" in the menu are not categories: one is the
  prices-drop page and the other is a brand page.

## Product listing (category page)

- Products: `#js-product-list article.product-miniature`. The product id is in `data-id-product`, the link is
  `a[href$=".html"]`.
- 12 products per page. Total count in `#js-product-list-top`: `Liczba produktów: 70`.
- A parent category also lists the products of all its subcategories (Kosmetyki: 741 products).
- Pagination: `ul.pagination button`. **These are buttons, not links.** The target URL is in the `data-ps-data` attribute
  (`...?page=2`).
  - Next page: `button.next[data-ps-data]`.
  - Last page: `button.next` has the `disabled` class (its `data-ps-data` then points to the current page).

## Product page

The best data source is the `data-product` attribute of `div.js-product-details`. It holds the full PrestaShop product
object as JSON. The JSON-LD `Product` block fills in the rest.

| Field | Source | Example / notes |
|---|---|---|
| id | `data-product.id_product` | `242` |
| Name | `data-product.name`, or `h1.product__name` | |
| Description | `data-product.description` (HTML); short description in `description_short` | Also rendered in `div.product__description` |
| Gross price | `data-product.price_amount` | `17.2`, already includes discounts |
| Price before discount | `data-product.price_without_reduction` | Differs only when `has_discount` is `true` |
| Net price | `data-product.price_tax_exc` | |
| VAT rate | `data-product.rate` | `23`, `8` (supplements); `tax_name` = `"VAT 23,00%"` |
| Default category | `data-product.id_category_default`, `category_name` | Full path in the JSON-LD `BreadcrumbList` |
| Brand | JSON-LD `Product.brand.name` | `data-product.manufacturer_name` is empty |
| EAN | JSON-LD `Product.gtin` | Missing on some products |
| Weight | JSON-LD `Product.weight.value` / `unitCode` | Missing on some products, and **the unit is unreliable** (see below) |
| Attributes | JSON-LD `size`, `color`, `material`, `pattern` + product family (see below) | `"size": "200 ml"`, `"pattern": "Amla"` |
| Images | `data-product.images[].bySize` | See below |

Not present on the page: `.product-variants`, `#product-details`, `dl.data-sheet`, or any other standard Classic theme
selector.

### Images

- Each entry in `data-product.images` has an `id_image`, a `legend` (alt text) and a `bySize` map with 12 sizes, from
  `small_default` (98 px) up to **`product_main_2x` (1440 × 1440 px)**.
- `product_main_2x` is the size to download: it is within the required 800–1600 px range. URL pattern:
  `https://www.magiczne-indie.pl/{id_image}-product_main_2x/{slug}.jpg`. A `.webp` version also exists.
- The sampled 1440 px JPEG weighs **311 KB**, just over the 300 KB limit, so images must be recompressed.
- Images per product, from the sitemap:

  | Images | 1 | 2 | 3 | 4 | 5 | 6+ |
  |---|---|---|---|---|---|---|
  | Products | 856 | 654 | 310 | 176 | 93 | 78 |

### Variants (product families)

- Native PrestaShop combinations were not observed: `id_product_attribute` was `0` on every one of 82 sampled products.
- Variants are **separate products** linked by the `ndx-family` module (`nav.ndx-family`). Each axis
  (`.ndx-family__axis`) lists options (`.ndx-family__opt`). The selected one is a `span.is-selected`, and the others are
  links to sibling products.
  - Example for product 242: axis 1 is sizes (100 / **200** / 300 ml), axis 2 is the oil type (**Amla**, Amla Gold,
    Argan, …).
- The HTML does not name the axes. Their meaning comes from JSON-LD (`size`, `pattern`, and possibly `color` and
  `material`).

## Gotchas

- **Weight unit:** JSON-LD always says `unitCode: "g"`, but the values do not match:
  - a 200 ml oil has `250.000000`, which looks like grams;
  - a large lamp has `1.187000`, which looks like kilograms.

  Store the raw value and decide how to convert it when importing into the shop.
- **Discounts:** `price_amount` is the current (discounted) price. Store `price_without_reduction` as well, so the
  regular price and the discount can be recreated in our shop.
- **Encoding:** pages are UTF-8 (`Content-Type: text/html; charset=utf-8`). Garbled Polish characters in a Windows
  console come from the console code page, not from the data.
- `img/p/` and the image size URLs are not blocked by robots.txt.

## Recommended crawl strategy

1. **Product URLs from the sitemap.** This takes 1 request instead of walking about 200 listing pages.
2. **Categories:** fetch each category URL from the sitemap (314 requests). Read the name from `h1` and the parent from
   the breadcrumb.
3. **Products:** fetch each product page (2167 requests). Parse `data-product` and the JSON-LD.
4. **Optional:** walk the leaf category listings with `?page=N`. This is only needed if we want every category a product
   belongs to, not just its default category and breadcrumb path.
5. **Images:** download `product_main_2x` for every image (about 4950 files), then recompress to ≤ 300 KB.

At 1 request per second, steps 1–3 take about 45 minutes and step 5 about 1.5 hours. This is why resuming matters.
